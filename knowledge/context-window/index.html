上下文窗口：AI的记忆力天花板

理解Context Window——为什么AI有时候'忘了'你说的话

上下文窗口Context WindowToken长文本

什么是上下文窗口

上下文窗口（Context Window）是大语言模型一次能处理的文本最大长度，通常用 Token 数量来衡量。

你可以把它理解为 AI 的”工作记忆”——超过这个长度的内容，AI 就”记不住”了。

什么是 Token

Token 是模型处理文本的最小单位。不等于一个字或一个词：

  • 英文：大约 1 个 Token ≈ 4 个字符，一个常见单词约 1-1.5 个 Token
  • 中文：大约 1 个汉字 ≈ 1-2 个 Token

举例：“我是律师” 大约是 4-6 个 Token。

上下文窗口的限制

模型上下文窗口
GPT-3.54K Token（约 3000 字）
GPT-48K-128K Token
Claude 3200K Token（约 15 万字）
GLM-5.31M Token（约 75 万字）

虽然窗口在不断扩大，但仍有边界。当你和 AI 聊了很久，或者输入了很长的文档，早期的内容可能会被”挤出去”，导致 AI “忘记”之前说过的话。

上下文窗口的实际影响

  1. 长文档处理：一份 50 页的合同（约 2 万字）需要约 3-4 万 Token，可能超出某些模型的窗口
  2. 多轮对话：对话越长，早期内容越容易被遗忘
  3. 成本：API 按 Token 计费，上下文越长费用越高

如何应对上下文限制

  • 分段处理：长文档分段输入，不要一次全塞进去
  • 关键信息前置：把最重要的信息放在输入的开头
  • 使用长窗口模型：对于需要处理长文档的场景，选择窗口更大的模型
  • 结合 RAG：让模型检索相关资料，而不是把所有资料都塞进上下文

法律视角联想

从合规角度看，上下文窗口限制意味着 AI 无法一次性完整审查超长合同或法规汇编，可能遗漏关键条款。法务部门在使用 AI 辅助审查时，应将长文档拆分为多个模块分别审查，再汇总结果，避免因技术限制造成审查遗漏。同时，上下文窗口的 Token 限制直接影响 API 调用成本，企业需要评估 AI 法务工具的使用频率和文档长度，合理规划预算。
