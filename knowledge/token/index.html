Token：模型眼里的最小单位

理解Tokenization——模型如何切分文本

token分词NLP

核心概念

Token 是大语言模型处理文本的最小单位。模型不直接读”字”或”词”，而是先把文本切分成一串 Token，再逐个处理。

一个 Token 可能是：

  • 一个完整的词（如 “hello”）
  • 一个词的一部分（如 “un” + “believ” + “able”）
  • 一个字符（如中文的每个字通常是一个 Token）
  • 一个标点符号

为什么重要

  • 计费单位：API 按 Token 数量收费，Token 越多费用越高
  • 上下文窗口：模型能处理的 Token 数量有上限（如 128K），超出的内容无法一次性输入
  • 理解模型行为：很多”模型犯错”其实是 Token 切分导致的——比如数不准一段文字里有几个字、对生僻词和长数字串的处理不稳定

实际影响

“ChatGPT” 被切分为 ["Chat", "G", "PT"] 三个 Token，而 “你好” 是 ["你", "好"] 两个 Token。英文平均 1 个 Token ≈ 4 个字符，中文约 1 个 Token 对应 1-2 个字。

对法务工作者的直观影响有两点：一是同样一份合同，中文版本消耗的 Token 往往多于英文版本，处理中文长文档的调用成本和窗口压力更大；二是金额、日期、编号等数字串常被切成多个 Token，模型在精确复述这类内容时容易出错——这正是 AI 输出中的关键数字必须人工核对的技术原因。

一句话记住

Token 是模型的”视觉单元”——模型看到的不是文字，是 Token。

法律视角联想

从合规角度看，Token 是 AI 服务的计量与计费单位，法务在审核 AI 采购合同或服务协议时，应关注按 Token 计费的条款、用量上限和超额处理规则，避免成本失控。同时，输入模型的每一个 Token 都可能携带敏感信息，提示词一旦发送即构成对外传输数据——哪些内容允许输入 AI、哪些禁止，应在企业数据管理制度中划定红线。
