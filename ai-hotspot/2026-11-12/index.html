第一部分｜今日 AI 观察

今日概念：模型评估与基准

模型评估与基准，解决的核心问题是：怎么科学地给大模型打分。当一家律所或投行面对市面上数十个模型，需要一个客观标尺来衡量谁更适合审查百页合同、谁更擅长解析附注密集的财报。

基准是一套标准化的测试题库，涵盖数学推理、代码生成、工具调用等维度；评估则是把模型放到这套题库上跑，输出准确率、延迟、成本等量化指标。业界有公开的 Arena 盲测排行榜，也有 Artificial Analysis 这类综合性价比指数。

这里有个关键陷阱：公开基准与你的实际业务可能严重脱节。OpenRouter 最新实测显示，其自定义任务评分与公开榜单的 Spearman 相关性仅为 0.109——几乎不相关。这意味着，看榜单选模型就像看高考总分招法务，分数最高的未必能读懂你的合同。科学评估的正确姿势是：用你自己的真实业务输入和预期输出契约，搭建私有基准，在相同任务上对比准确率、成本和耗时。

热点一：百度发布”词元所”大模型交易平台，引入信用评级

百度世界大会 2026 上，李彦宏发布大模型服务平台”词元所”，定位为中立、可信的交易平台，类比证券交易所汇聚模型与提供商。平台对模型做准入测试并持续监测，防止偷换模型、虚标参数，同时从服务质量、兑现度、安全合规、商业履约等维度给提供方打分并给出信用评级，形成公开可查的信用档案。上线一个月日均调用 Token 数已突破 7000 亿。

技术上，词元所做了一件行业缺位已久的事：把模型从”一次性采购”变成”持续受信交易”。防止偷换模型（provider 私自降配或蒸馏）和虚标参数，需要平台具备持续的红队抽测和输出分布监测能力。对开发者而言，这意味着选模型不再只看首发评测，而是看动态信用档案；对企业采购而言，合规履约维度的评级直接降低了供应商尽职调查成本。

热点二：OpenRouter 发布自定义基准测试教程，公开榜单失灵

OpenRouter 发布教程，讲解如何用应用的真实输入和输出契约评测 LLM。方法很直接：拿你的业务任务，对不同模型跑相同测试，对比准确率、计费成本和请求耗时。在其 60 个合成任务上，GPT-6.1 Sol 三次重复全部通过 180/180，DeepSeek 成本最低、通过 157/180。最震撼的结论是：这套自定义评测与 Artificial Analysis 公开榜单的相关性仅 0.109。

这个数据点极具破坏力。它证明公开榜单衡量的是”模型在通用基准上的能力”，而非”模型在你的具体业务上的表现”。一个在 Arena 上排名靠前的模型，可能在你的合同审查任务上频繁幻觉。OpenRouter 的教程给出了技术解法：构建私有评测集，用真实输入输出契约做 ground truth，通过多次重复测试验证稳定性。这是企业级 AI 采购从”看评测”走向”做评测”的分水岭。

热点三：谷歌发布 Gemini Decisions API，单次千问毫秒级决策

谷歌推出 Gemini Decisions API，由全新 Gemini Decision 1 模型驱动。该模型可在一次快速处理中对文本、图像、视频和 PDF 内容进行至多 1000 项是非判断、选项选择和标准评估。定价为输入每百万 tokens 0.10 美元，输出 token 计费为零，上下文窗口达 26 万 tokens，端到端延迟在 150-250 毫秒。

这并非通用对话模型，而是专用的决策引擎。技术上，它把”判断”这一高频原子操作做了极致优化：单次请求批量处理上千个校验点，毫秒级返回校准概率。对开发者而言，这意味着过去需要多轮 prompt 工程才能完成的清单合规检查、标准对照打分，现在可以一次 API 调用搞定。零输出计费也改变了成本结构——你只为输入的信息密度付费，判断结果本身不产生额外成本。

热点四：实测 Claude 系列，升一档比拉满 effort 更划算

Artificial Analysis 分析当前 Claude 系列的 Intelligence Index 与 Cost per Task，得出一个反直觉结论：升一档模型比拉满推理 effort 更能实现每美元智能最大化。这与 Anthropic 刚为 Claude API 新增的 effort 调节能力直接相关——开发者可在消息序列中途通过空 system 消息切换模型投入档位。

技术上，effort 参数控制的是模型在单次推理中投入的计算量（类似思考链长度）。实测表明，在低档模型上拉满 effort，成本飙升但智能提升边际递减；而直接换用高一档的模型，同等成本下智能表现更优。这对工程实践的指导很明确：不要用”小模型拼命想”来硬啃难题，任务路由应优先按复杂度匹配模型档位，effort 调节留给同一档位内的微调。

热点五：OpenRouter 正式并入 Stripe，交易金额约 75 亿美元

Stripe 宣布 AI 模型聚合平台 OpenRouter 正式并入，据《纽约时报》报道交易金额约 75 亿美元。双方表示将帮助企业探索新商业模式，优化 Token 路由和用量管理。

这笔并购的技术意义在于：AI 模型的调用计费正在深度嵌入支付基础设施。OpenRouter 此前解决了”一个 API key 路由上百个模型”的技术问题，并入 Stripe 后，模型调用的计量、结算、对账将与企业财务系统原生打通。对开发者而言，Token 路由不仅是技术选型，更是财务决策；对企业而言，AI 算力采购的账单流、预算控制、成本分摊将像支付网关一样标准化。

第二部分｜每日一个创意 AI 应用深度解析

创意名称：动态路由与信用评级驱动的智能模型采购风控引擎

创意是什么： 一套面向法律与金融机构的 AI 模型采购与运行时风控系统，用企业私有基准替代公开榜单做选型，接入交易平台信用档案做供应商尽调，并在运行时按任务复杂度动态路由模型档位，实现”选得准、管得住、花得值”。

灵感来自哪些热点： 本创意直接由热点一（百度”词元所”引入信用评级与持续监测）、热点二（OpenRouter 自定义基准与公开榜单相关性仅 0.109）、热点三（Gemini Decisions API 毫秒级千问决策）、热点四（升一档模型比拉满 effort 更划算）和热点五（OpenRouter 并入 Stripe 打通计费与支付）组合而来。词元所提供了交易平台信用档案的数据源；OpenRouter 的教程提供了私有评测的方法论；Gemini Decisions 提供了运行时批量校验的技术底座；effort 实测结论提供了路由策略的优化方向；Stripe 并购则提供了计量计费标准化的财务闭环。

为什么现在可行： 三个条件刚刚成熟。第一，交易平台开始提供结构化的供应商信用档案（热点一），模型采购终于有了像债券评级一样的参考标的；第二，自定义基准测试有了可复用的工程框架（热点二），企业不必从零造轮子；第三，决策类 API 的极低延迟和批量判断能力（热点三），让运行时实时风控的成本降到了可忽略的水平。三者叠加，“动态选型 + 运行时风控”不再是概念，而是可以落地的工程方案。

专业场景怎么用：

法律场景——合规审查与合同质检： 律所在审查跨境并购的数百份附属协议时，系统按任务复杂度自动路由：标准保密协议用低成本模型快速过；关键赔偿条款切换至高智能档位模型深度解析。同时，调用 Gemini Decisions API 对每份文档批量执行千项合规清单校验（如条款是否触发反垄断申报阈值、管辖权条款是否与主合同一致），毫秒级返回校准概率，低概率项才触发人工复核。

金融场景——投研尽调与风控监测： 投行在尽调阶段，用系统对目标公司的财报附注、法律意见书、专利文件做多模型交叉验证。不同模型解析同一份附注，若结果出现重大分歧（如对抵押品释放的识别不一致），系统自动标记为高风险信号。模型供应商的信用档案若显示近期有”偷换模型”或”安全合规”评级下调记录，系统自动触发采购熔断，暂停该供应商在核心业务流的调用，同时启动替代模型切换。

落地要点：

第一，以业务真实输入输出契约评测模型，替代公开榜单盲选。 法务和合规团队抽取过去 12 个月的真实合同审查案例，标注预期输出（如风险条款清单、义务矩阵），构建不少于 200 条任务的私有评测集。每次选型或供应商续约前，对候选模型跑三轮评测，以通过率和单任务成本作为核心决策指标。谁来做：法务科技团队牵头，IT 基础设施团队提供评测环境。风险在于标注质量——若 ground truth 本身有误，评测结论会系统性偏差，建议引入双人交叉标注机制。

第二，接入平台信用档案与动态监测数据，模型替换触发合规熔断。 对接”词元所”等交易平台的 API，持续拉取当前供应商的信用评级、安全合规评分和履约记录。设定阈值：若安全合规评分单周下调超过一档，或平台发出”模型偷换”预警，系统自动将该供应商的调用降权至只读查询，核心业务路由切换至备用模型，同时向合规官发送审查工单。谁来做：合规部门设定阈值规则，采购部门维护供应商主数据。风险在于平台监测的覆盖面有限，企业仍需保留独立的输出分布抽检能力。

第三，按任务复杂度路由模型档位，升档替代拉满 effort 实现成本最优。 建立任务分级路由表：文档分类、格式校验等低复杂度任务路由至轻量模型；条款冲突检测、赔偿计算等高复杂度任务直接路由至高智能档位，不在低档模型上浪费 effort 预算。结合 OpenRouter 并入 Stripe 后的标准化计费，系统按项目维度自动归集 Token 成本，生成可对接财务系统的费用分摊报告。谁来做：业务部门定义任务分级，IT 部门实现路由逻辑，财务部门对账核销。风险在于路由规则需要持续校准——任务分级若过粗，高复杂度任务误判为低复杂度会导致输出质量事故。

价值与局限： 对法律和金融专业人士而言，这套系统的核心价值是把 AI 模型采购从”凭感觉看榜单”升级为”凭数据做尽调”，把运行时从”一个模型用到黑”升级为”按任务动态调度”。但它不该用于涉及客户隐私数据或未脱敏机密信息的场景——在数据合规边界未明确时，私有评测集和运行时路由都应优先在隔离环境中运行。此外，信用评级是滞后指标，它能告诉你”这家供应商昨天是否可信”，但无法预测”这家供应商明天是否会出事”。人的判断，依然是最后一道关。
