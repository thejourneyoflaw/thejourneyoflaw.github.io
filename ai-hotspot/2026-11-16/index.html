第一部分｜今日 AI 观察

今日概念：RAG 检索增强生成

RAG（Retrieval-Augmented Generation，检索增强生成）是一种让大语言模型在回答问题前，先去外部知识库里检索相关信息，再把检索到的内容作为上下文喂给模型的技术方案。它解决的核心问题是：大模型的知识停留在训练截止日，且无法访问企业的私有数据。

打个比方，大模型本身像一个博学但没有当天报纸的教授，你问他今天的股价，他只能凭旧印象胡猜。RAG 就是给这位教授配了一台联网的平板电脑，他回答前先查一下实时数据库，再把查到的信息揉进自己的推理过程里给出答案。

对于法律与金融专业人士，RAG 的价值尤为直接：合同审查、尽调材料、招股书分析往往涉及海量非公开文档，直接让模型”硬背”这些机密既不现实也不安全。RAG 让模型在每次回答时只检索相关的文档片段，既减少了”幻觉”编造法条或财务数据的风险，又实现了数据可用不可见的权限隔离。今天我们看 Qwen4-Max 把上下文拉到百万 token，其实就是在拓宽这位教授的”临时书桌”——让他一次能摊开更多资料再作答。

热点一：Qwen4-Max 发布，2.4万亿参数MoE架构，任务成本降超60%

阿里通义千问团队正式发布新一代旗舰模型 Qwen4-Max，采用 2.4 万亿参数的稀疏 MoE（专家混合）架构，每 token 激活 71B 参数。模型原生支持文本、图像和视频输入，提供 100 万 token 上下文窗口。最关键的数据在于 token 效率：在 Work360 评测中，相比上一代 Qwen3.8-Max，token 用量约下降 24% 至 35%，Terminal-Bench 4.0 上降幅达 48% 至 49%，平均单任务成本从 $4.43 降至 $1.67。定价方面，输入 $1.50/M、输出 $4.50/M，隐式缓存低至 $0.075/M。这意味着长文本处理与长程智能体任务的经济门槛被大幅拉低，过去因 token 成本过高而无法跑通的复杂多步推理任务，现在具备了规模化部署的商业可行性。

热点二：腾讯总办号召面向AI时代再创业，WorkBuddy成最大token产品

腾讯在 28 周年生日当天公布年度总办 LinkTime 播客原文，将智能革命定义为”不进则退的生死问题”，要求所有核心业务面向 AI 时代再创业、组织扁平化、打破山头主义。腾讯透露其 AI 金字塔核心模型已进入国内第一梯队，WorkBuddy 在 8 个月内成为中国提供最多 token 的单一 AI 产品。元宝定位为决策资讯参谋，小微目标是让大家实现 token 自由。从企业战略层面看，这是头部互联网公司首次如此明确地将 token 消耗量作为核心业务指标，标志着 AI 从”辅助工具”向”核心生产力底座”的组织级迁移。

热点三：谷歌 Project Zero 缩短漏洞披露期限至30天

谷歌 Project Zero 于 11 月 13 日发布全新漏洞披露政策，将分阶段把漏洞披露期限从 90 天缩短至 30 天。官方给出的理由是：AI 辅助漏洞挖掘与利用技术的兴起，使现有 90+30 天政策难以适应安全节奏。这反映了 AI 正在实质性改变网络安全攻防的时间窗口——当 AI 能在数小时内完成过去需要安全团队数周才能完成的漏洞分析与利用链构造，留给企业修补的时间被急剧压缩。对于依赖第三方开源组件的法律合规与金融风控团队，这意味着供应商漏洞响应条款的 SLA 谈判基准需要同步前移。

热点四：美团开源 LongCat-2.5，1.6万亿参数全程未用 Nvidia GPU

美团开放 LongCat-2.5 权重，这是一款面向智能体的 1.6 万亿参数 MoE 模型，每 token 激活约 480 亿参数，采用 MIT 许可证。最具标志性的细节是：官方部署方案基于 194 片华为 Ascend 加速器，训练全程未使用 Nvidia GPU。在当前 AI 芯片出口管制持续收紧的背景下，这证明了国产算力在万亿参数级模型训练上的工程闭环已经跑通。对于需要本地化部署且对供应链合规有严格要求的大型金融机构与律所，非 Nvidia 依赖的开源大模型提供了一条绕开地缘政治风险的基础设施路径。

热点五：Databricks 发布 Genie One 技能指南，工作流教给 AI

Databricks 发布 Genie One 技能（Skills）使用指南，技能是以开放 Agent Skills 格式写下的工作流配方，可让 Genie One 按团队固定步骤、检查和格式产出结果。这项能力的本质是把”团队 SOP”转化为智能体可执行的代码化工作流。过去 AI 只能完成单步任务，现在可以把”先查数据库、再校验规则、最后按模板输出报告”的完整流程固化下来让 AI 自动跑。对于合规审查和投研流程这种步骤严密、格式要求高的专业场景，技能化封装让 AI 从”聊天助手”变成了可审计的流程执行节点。

第二部分｜每日一个创意 AI 应用深度解析

百万上下文低成本驱动的尽调与合同智能体引擎

创意是什么：一个以百万 token 上下文窗口和极低缓存成本为技术底座，将全套尽调材料、合同文本与合规规则一次性注入模型并自动执行长程多步审查的智能体引擎。

灵感来自哪些热点：本创意直接源自热点一（Qwen4-Max 发布）和热点五（Databricks Genie One 技能指南）。热点一贡献了两个核心技术条件：100 万 token 上下文窗口让整套尽调材料或合同附件可以一次性喂入模型，不再依赖碎片化检索；隐式缓存 $0.075/M 的超低定价则让高频重复调用同一批参考文档的成本降至可忽略。热点五贡献了工作流固化能力，把法律与金融团队固有的审查步骤封装成 Agent Skills，确保每次执行都有固定检查点和格式化输出。

为什么现在可行：过去做合同审查或尽调的 AI 方案，最大瓶颈是上下文不够长——一份 200 页的招股书加上附件轻松超过 20 万 token，模型根本放不下，只能切片检索，导致跨章节关联分析断裂。另一个瓶颈是成本：反复把几十万 token 的上下文发给模型，单次审查费用可能高达数十美元。Qwen4-Max 的百万上下文和 token 效率提升（单任务成本从 $4.43 降至 $1.67）让”全量注入 + 多轮深挖”的范式在经济上首次成立。

专业场景怎么用：在法律尽调场景，把目标公司的全套工商档案、重大合同、诉讼卷宗一次性注入模型，用 Agent Skills 定义”先扫描关联交易条款、再比对诉讼标的金额、最后输出风险矩阵”的固定流程。在金融风控场景，把发债主体的审计报告、评级报告与行业研报同时喂入，让智能体交叉比对抵押品释放条款与现金流覆盖倍数。在合规审查场景，将新版监管规则与企业内部合同模板库同时注入，让模型逐条扫描模板中的违规敞口。

落地要点：

第一，以百万 token 上下文窗口为底座，将全套尽调材料与合同文本一次性注入模型，构建长程智能体任务流。技术团队负责搭建文档预处理管道，确保 PDF、扫描件和表格统一转为模型可读结构；关键风险在于文档注入前的数据脱敏，必须由合规团队确认哪些字段可以在外部模型中暴露。

第二，利用隐式缓存机制压缩重复检索成本，为高频调用的合规校验与风控巡检建立固定工作流配方。利用 Qwen4-Max 的隐式缓存，把监管规则库和合同模板库作为常驻上下文缓存，每次只变更待审查的目标文档，把单次合规校验的边际成本压到极低；风险点在于缓存失效策略，当法规更新时必须强制刷新缓存层。

第三，将模型路由与 token 效率监控嵌入风控台账，实时追踪单任务成本下降比率并生成审计日志。金融与法律场景对过程可审计性要求极高，必须记录每次模型调用的输入 token 数、输出内容、缓存命中率和成本，形成可供监管检查的完整调用链条。

价值与局限：这个创意的核心价值在于把过去需要初级律师或分析师数天才能完成的全量文档交叉比对，压缩到分钟级，且成本可控。但局限同样明确：模型对复杂商业意图的判断仍不可替代人类专家，尤其在”实质重于形式”的合规定性问题上；此外，涉及客户机密数据的场景必须走本地化部署或私有化托管，不能直接调用公有云 API，这也意味着需要结合热点四中非 Nvidia 算力的开源部署方案来满足数据驻留要求。
