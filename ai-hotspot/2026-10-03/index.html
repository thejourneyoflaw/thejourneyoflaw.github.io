第一部分｜今日 AI 观察

今日概念：模型评估与基准

基准测试是科学衡量 AI 模型能力的标尺。简单来说，就像金融行业用夏普比率衡量风险调整后收益、用不良贷款率衡量资产质量一样，AI 行业用基准来回答”这个模型到底行不行”。

基准测试解决三个核心问题：第一，能力量化——把”感觉不错”变成”准确率 87%“这样的可比较数字；第二，公平比较——不同模型在相同测试集上跑同一套题，减少主观偏差；第三，持续追踪——版本迭代后能力是涨了还是退步了，需要可复现的测量方法。

一个直观的技术类比：基准就像法考。每年同一套大纲、同一种题型，考生（模型）的成绩才有横向可比性。但现实中，光看总分（整体准确率）远远不够。一个模型可能在合同审查基准上得分很高，但在财务计算基准上表现糟糕，就像一个律师法考高分但看不懂资产负债表。因此，现代评估越来越强调多维基准矩阵——按任务类型、成本、延迟分别打分，再用加权评分综合排序。今天 OpenRouter 推出的 Router Index 就是这种多维评估思路的典型实践。

热点一：OpenRouter发布路由器基准，质量60%时间20%成本20%加权

OpenRouter 为每个基准推出 Router Index 评分，权重为质量 60%、单任务时间 20%、成本 20%。用户可在页面上拖动滑块调整权重，按自身优先级查看领先模型。这是模型评估领域从”单一准确率”向”多维权衡评分”转变的标志性动作。对开发者而言，这意味着选择模型不再靠口碑或直觉，而是可以按业务场景（高精度需求调高质量权重、实时场景调高时间权重）精确量化取舍。

热点二：OpenRouter对比七款路由器，揭示切换并非总是更好

OpenRouter 推出 Model Router Benchmarks，可并排比较 7 款路由器在 6 项基准上的质量、速度和成本。同时，官方坦诚指出路由器并不总是更好——切换模型需要重建输入缓存，任务复杂度难以从提示词判断，选择逻辑还会增加延迟。这打破了”路由器万能”的迷思，把路由选择本身变成了一个需要基准测试来回答的工程问题。

热点三：OpenAI介绍dot智能体，学习用户习惯并协调Codex任务

OpenAI Developers 介绍了 dot 的能力：学习用户工作方式、跨应用保持上下文、协调 Codex 任务并标记需要用户关注的事项。作者称 dot 是使用 Codex 的首选方式，主动性减少了心智负担。dot 的核心突破在于从”被动响应”转向”主动协调”——它不只是执行单条指令，而是理解用户的工作流模式，跨应用串联任务。这对需要多工具协同的复杂专业工作（如尽调、合同审查）具有直接启发。

热点四：分析师体验Meta Muse后清仓Airbnb，AI或削弱平台流量入口

独立股票分析师在测试 Meta 的 Muse AI 智能体约 10 天后清仓了 Airbnb 并加仓 Meta，认为 AI 智能体可能削弱平台流量入口。这一决策值得金融专业人士关注：当用户通过 AI 智能体完成预订、搜索等操作时，传统平台的流量分发地位可能被架空。这直接影响平台型公司的估值逻辑——如果用户不再打开 Airbnb App 而是通过智能体完成交易，平台的中介溢价将受到结构性压缩。

热点五：OpenAI DevDay盘点智能体优化四杠杆

OpenAI DevDay 笔记指出，构建智能体应用优化成本与性能的四个关键杠杆是：prompt caching、reasoning effort、programmatic tool calling 和 batch request。并强调建议熟悉这些杠杆并用 evals（评估）进行测量。这四个杠杆本质上都是成本与质量的调节阀，而 evals 是测量调节效果的仪表盘。这与 OpenRouter 的多维基准测试形成呼应——行业正在从”大力出奇迹”转向”精细调参+量化评估”的工程化阶段。

第二部分｜每日一个创意 AI 应用深度解析

创意名称：多路由加权投研尽调智能体引擎

创意是什么： 一个基于多模型路由器的投研尽调引擎，将并购尽调任务按法律合规与财务分析双线拆解为子任务，通过可调权重的路由器在多个模型间动态切换，在质量、时间、成本三维之间实现精准权衡。

灵感来自哪些热点： 本创意直接源于热点一、热点二、热点三和热点五。热点一和热点二（OpenRouter Router Index 与路由器基准）提供了核心方法论——多维加权评分（质量60% / 时间20% / 成本20%）和路由器并非总是更好的坦诚判断，让”按场景调权重”成为可操作的工程实践。热点三（OpenAI dot 智能体）提供了任务协调层的技术条件——dot 能学习用户工作习惯、跨应用保持上下文、协调多任务并标记需关注事项，这正是尽调场景需要的”总协调员”。热点五（DevDay 四杠杆）则提供了底层优化手段，prompt caching 和 reasoning effort 的调节与路由切换深度耦合。

为什么现在可行： Router Index 的可调滑块把”质量-时间-成本”三角变成了可量化、可调节的参数组合，而非不可言说的经验直觉。dot 证明了智能体可以跨应用协调复杂工作流。两者结合意味着：一个能理解尽调流程、能按子任务特征动态切换模型、能在三维权重间精细权衡的引擎，技术条件已经成熟。

专业场景怎么用： 在并购尽调中，法律团队需要审查数百页合同（识别控制权变更条款、竞业限制、知识产权归属），金融团队需要勾稽财务数据（收入确认政策、关联交易、表外负债）。传统做法是人工分组并行，质量靠人盯。本引擎的做法是：将尽调拆解为合同条款审查、财务勾稽验证、行业图谱构建等子任务，每个子任务标注”质量敏感度”和”时间敏感度”。合同审查是高质量敏感任务——一个漏掉的控制权变更条款可能导致交易结构推倒重来，路由器分配质量权重80%。行业图谱构建是时间敏感任务——初筛阶段快速定性比深度分析更重要，路由器分配时间权重50%。引擎自动为每个子任务选择最优模型，并在任务完成后生成一份包含路由决策日志、模型选择理由、质量评估分数的完整报告。

落地要点：

第一，以 OpenRouter Router Index 为原型，将尽调任务拆解为条款审查、财务勾稽、行业图谱等子任务，按质量60%、时间20%、成本20%动态分配路由权重。尽调团队负责人拥有滑块调节权，在时间敏感的竞标项目中向时间维度倾斜，在日常合规审查中向成本维度倾斜。每次调整自动生成评估报告，记录权重变更理由与对应模型选择，确保决策可追溯。

第二，法律与金融条线各设评估基准：合同合规用条款级准确率衡量质量，财务模型用勾稽偏差率衡量。路由器自动切换模型并记录决策日志。法律条线的基准集应包含已知答案的合同条款识别测试题（如”以下100份合同中哪些含控制权变更触发条款”），金融条线应包含已知勾稽关系的财务报表测试集。路由器在每次切换模型时，将选择理由、预期质量分数、实际输出与基准答案的偏差一并记录。

第三，引用热点五的 prompt caching 和 reasoning effort 杠杆进行底层优化。对重复出现的尽调模板（如标准合同审查清单），利用 prompt caching 降低成本；对高风险条款的深度分析，调高 reasoning effort 提升推理深度。同时，正视热点二揭示的路由器局限——切换模型需重建输入缓存、增加延迟——因此对延迟敏感的实时交互场景（如尽调现场与客户问答），应锁定单一模型而非频繁切换。

价值与局限： 这个引擎的价值在于把尽调中的模型选择从”拍脑袋”变成了”看数据”，把质量-成本-时间的权衡从”不可见”变成了”可审计”。但它不该用于最终决策——路由器选出的模型输出仍需专业人工复核，尤其在合同条款解释和财务异常判断上，AI 的角色是”放大镜”而非”裁判官”。路由器本身的选择逻辑也可能出错，热点二已经坦诚揭示了这一点。因此，引擎输出必须保留人工否决权，且每次路由决策日志应作为尽调工作底稿的一部分留存，以应对后续可能的质量争议或监管检查。
