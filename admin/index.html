⚙️ 生成控制台

本站是纯静态站点：访客看到的页面永远只读；内容生产由下面的流水线完成，密钥只存在于 .env 或 GitHub Secrets，绝不进仓库。

⏰

每日自动生成（推荐）

GitHub Actions 每天北京时间 7:10 自动调用 AI 生成当日的英语精读与 AI 观察并提交仓库，托管平台随之自动重新部署，访客无感知。

推送代码后在本仓库 Actions 页查看运行记录
🖱️

手动触发（补卡/出差）

在 GitHub 仓库 Actions → Daily Content → Run workflow，可选轨道（法律/AI/商务/全部）、指定日期、是否覆盖。

gh workflow run daily-generate.yml -f track=all
💻

本地生成

在项目根目录配置 .env 后运行脚本；生成的 MDX 在 src/content/daily-english/，确认后提交即可发布。

npm run generate:daily:all

🔑 模型接入（双协议可切换）

生成脚本通过 scripts/lib/ai-client.mjs 同时支持 OpenAI 兼容协议与 Anthropic 消息协议，改一个环境变量即可换服务商或模型。

变量 说明 示例
AI_PROVIDER openai 或 anthropic，决定用哪套协议 openai
AI_BASE_URL OpenAI 类填到 /v1 结尾；Anthropic 类填到域名根 https://token.sensenova.cn/v1
AI_API_KEY 对应服务的密钥 sk-xxx
AI_MODEL 模型名，随时可换 glm-5.2

👥 权限划分

  • 管理员（你）：拥有 GitHub 仓库推送权限的人——能触发生成、能改 .env/Secrets、能改内容与样式。
  • 访客（公网）：只能浏览页面，无法触发任何生成或修改。
  • 若需要给管理员入口再加一道锁，部署后可在托管平台（如 Cloudflare Zero Trust）对 /admin/ 路径套一层访问认证。

🔑 Key 失效恢复

症状：Actions 定时任务报红 / 当日内容缺失

  1. 仓库 Settings → Secrets and variables → Actions
  2. 更新 AI_API_KEY（或 AI_BASE_URL / AI_MODEL）
  3. Actions → Daily Content → Run workflow（可填失效那天的日期）
  4. 生成并自动提交 → Pages 自动重新发布

本地等价命令：

改 .env 后： node scripts/generate-daily.mjs --force --date=YYYY-MM-DD 观察文章： node scripts/generate-hotspot.mjs --force --date=YYYY-MM-DD
